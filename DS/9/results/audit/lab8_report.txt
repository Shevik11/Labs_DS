Тема та мета роботи
Тема  —  збереження  знань візуалізації  енергетичних  даних у графовій  базі  
Neo4j.  Мета  —  перетворити  онтологію  попередніх  робіт  на  графову  структуру,  
імпортувати  поняття  й  фактичні  дані,  розробити  запити  та  перевірити  ефект  
індексації.
Завдання
1. Ознайомитися з графовими базами даних і підключитися до Neo4j.
2. Визначити вузли, властивості та зв’язки для онтології.
3. Підготувати JSON/CSV і виконати імпорт через Cypher.
4. Перевірити повноту даних і візуалізувати графові запити.
5. Створити індекси та виміряти продуктивність складних запитів.
1 Предметна область та середовище
Тематичний  напрям  роботи  —  енергетика,  програмне  забезпечення  та  
візуалізація.  Предметна  область  охоплює  вимірювання  електроспоживання,  їх  
часову  організацію,  аналітичні  результати  й  графічні  подання.  Основою  є  
семантична онтологія лабораторної №6.
Роботу виконано у Neo4j Sandbox через Neo4j Browser та офіційний Python-
драйвер. Віддалений сервер — Neo4j Enterprise 2026.04.0, клієнт — Python 3.11.6 і  
neo4j  5.28.2.  Перетворення  OWL  виконано  RDFLib  7.1.4.  Усі  наведені  основні  
вимірювання отримано у Sandbox.

9 Контроль значень і повноти
Похибку  регресії повторно  обчислено  безпосередньо  в  Neo4j через зв’язок  
прогнозу з фактичним вимірюванням. Використано всі 9 530 збережених прогнозів.  
Відповідний запит і результат показано на рис. 8.
Рис. 8 — MAE на повній тестовій вибірці
Середня абсолютна похибка визначається як MAE = (1/n) Σ |ŷᵢ − yᵢ|, де n —  
кількість  прогнозів,  ŷᵢ  —  прогноз,  yᵢ  —  фактична  енергія.  Для  Random  Forest  
отримано  0,335966  kWh;  для  базового  прогнозу  незмінного  навантаження  —  
0,423517 kWh. Результати збігаються з №1 в межах похибки обчислень.
Ця  перевірка  підтверджує  збереження  значень  та  правильність  зв’язування  
прогнозів  із  фактами,  а  не  нове  навчання  моделі.  Усі  цільові  мітки  часу  та  
actual_kwh перевірено за hourly_clean.csv.
Повний часовий ряд має 502 відсутні години всередині його меж. Наявні 34  
085 записів відповідають повним годинам; пропущені інтервали не заповнювалися.  
Дослідження  стосується  одного  домогосподарства  Франції  з  UCI,  а  не  всієї  
енергосистеми.

def node_statement(labels, temporal):
    query = 'UNWIND $rows AS row\nMERGE (n:Lab8Entity {id: row.id})\nSET n += 
row.properties\n'
    extra = [x for x in sorted(labels) if x != BASE_LABEL]
    if extra:
        query += 'SET n' + ''.join(':' + x for x in extra) + '\n'
    for key in sorted(temporal):
        query += f'SET n.{key} = localdatetime(row.properties.{key})\n'

def run(session, query, parameters=None):
    started = time.perf_counter()
    result = session.run(query, parameters or {})
    rows = [serial(dict(record)) for record in result]
    summary = result.consume()
    elapsed_ms = (time.perf_counter()-started)*1000
    return rows, summary, elapsed_ms
def plan_totals(plan):
    hits, rows, operators = 0, 0, []
    pending = [plan]
    while pending:
        item = pending.pop()
        if not item:
            continue
        hits += item.get('dbHits', 0)
        rows += item.get('rows', 0)
        operators.append(item.get('operatorType', ''))
        pending.extend(item.get('children', []))
    return {'db_hits_sum': hits, 'operator_rows_sum': rows, 'operators': 
operators}
